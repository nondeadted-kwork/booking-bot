# Как сломать бота и что при этом будет

Когда заказчик пишет «упало», сначала смотрим сюда. Первая команда во всех случаях:
`docker compose logs --tail 100 bot`.

Сценарии 3, 7–10 проверяются автотестами (`pytest`), 4–6 — запуском с испорченным конфигом,
остальные — вручную на живом сервере.

| # | Что ломаем | Как воспроизвести | Что происходит | Как чинить |
|---|---|---|---|---|
| 1 | **Сервер упал / процесс убит** | `sudo pkill -9 -f 'python -m bot'` или `sudo reboot` | `restart: unless-stopped` поднимает контейнер. Напоминания и брони лежат в SQLite. После старта фоновый цикл досылает всё, что попадает в окно, и ничего не шлёт дважды (`reminded_at`). Старые кнопки работают: вся навигация хранится в `callback_data` | Ничего |
| 2 | **Пропал интернет** | `docker network disconnect booking-bot_default booking-bot-bot-1`, через 2 минуты `connect` обратно | aiogram пишет `Failed to fetch updates` и переподключается с нарастающей паузой. Напоминание, которое не удалось отправить, остаётся непомеченным и уходит на следующем тике | Ничего |
| 3 | **База заблокирована / диск отвалился** | тест `test_database_failure_is_reported_to_client_and_owner` | Клиент видит «⚠️ Что-то пошло не так», владелец получает алерт с текстом ошибки (один раз в 5 минут на тип ошибки). Фоновый цикл логирует ошибку и продолжает работать | `df -h` (кончился диск?), `ls -la data/` (права?) |
| 4 | **База повреждена** | записать мусор в `data/bot.db` | Бот не стартует и пишет: `База … не открывается (file is not a database). Восстановите из бэкапа: cp backups/…` | `cp backups/bot-<дата>.db data/bot.db && docker compose restart` (бэкапы делает `deploy/backup.sh`) |
| 5 | **Неверный или отозванный BOT_TOKEN** | испортить токен в `.env` | Бот не стартует: `BOT_TOKEN неверный. Скопируйте токен заново из @BotFather` | Новый токен в `.env`, `docker compose up -d` |
| 6 | **Неверный PAYMENT_TOKEN** | `PAYMENT_TOKEN=123:TEST:broken` | Счёт не выставляется. Бронь снимается сразу, а не висит 15 минут. Клиенту предлагается «оплачу на месте», владелец получает алерт «проверьте PAYMENT_TOKEN» | Токен из @BotFather → Payments |
| 7 | **Двое жмут одно время одновременно** | тест `test_race_for_one_slot_has_single_winner` (10 параллельных попыток) | Запись получает ровно один. Второму бот пишет «😔 Это время только что заняли» и показывает свободные окна | Ничего, так задумано |
| 8 | **Оплатил, а бронь уже истекла** | тест `test_expired_hold_rejects_payment` | Telegram отказывает ещё до списания денег (`pre_checkout_query`): «Бронь истекла, выберите время заново» | Ничего |
| 9 | **Деньги списались, а слот занят** | тест `test_payment_after_slot_was_taken_is_conflict` | Клиенту приходит честное сообщение, владельцу — «⚠️ Нужен возврат» с id платежа | Возврат в кабинете ЮKassa |
| 10 | **Кривые данные в кнопке** | прислать callback `slot:cut:not-a-number`, тест `test_garbage_callback_does_not_crash` | «Кнопка устарела — откройте меню заново», без исключения | Ничего |
| 11 | **Клиент заблокировал бота** | заблокировать и дождаться напоминания или рассылки | Пользователь помечается `is_blocked`, в отчёте рассылки он в графе «заблокировали». После `/start` флаг снимается | Ничего |
| 12 | **Запустили второй экземпляр** | `python -m bot` рядом с docker | Telegram отдаёт `Conflict: terminated by other getUpdates request`, оба экземпляра ругаются в логах | Остановить лишний: `ps aux \| grep bot` |
| 13 | **Сервер в UTC, клиент в Москве** | `TZ=UTC` на сервере | Время считается в `TZ_NAME` из `.env`, от часового пояса сервера не зависит | Ничего |
| 14 | **Сообщение больше 4096 символов** | 100+ записей за неделю в «🗓 7 дней» | Список обрезается по целым дням, HTML не рвётся, в конце подсказка про CSV | Ничего |

## Быстрая диагностика

```bash
apt install -y sqlite3                    # один раз, нужен для просмотра базы и deploy/backup.sh
docker compose ps                         # контейнер жив?
docker compose logs --tail 100 bot        # что было перед падением
sqlite3 data/bot.db "select id, status, datetime(start_at,'unixepoch','+3 hours') from bookings order by id desc limit 10;"
docker compose restart bot                # перезапуск без потери данных
```
